# My Chat

> **Language / 언어:** English | [한국어](README_KO.md)

A ChatGPT-style FastAPI web app with three fixed sample accounts (`user1`, `user2`, `user3`), and a real-world example of building with the **GitHub Copilot SDK** and **Copilot CLI**. All AI inference and model discovery come from GitHub Copilot; Microsoft Foundry is used solely as the **Hosted Agent runtime** that executes custom Python code.

> No Foundry model deployment is created. The Foundry project defined in `azure.yaml` contains no model deployments; every response is generated by GitHub Copilot models via the `github-copilot-sdk`.

## Features

- Three fixed user accounts with complete per-user data isolation
- Forced password change on first login using a shared temporary bootstrap password
- Argon2 password hashing, login lockout, signed session cookies, and CSRF protection
- Runtime discovery of models available to the connected GitHub Copilot account
- Multi-model chat: GPT-5.6 Sol/Terra/Luna, Claude Opus 5/Sonnet 5/Haiku 4.5, and the latest Gemini/MAI models
- Per-model reasoning effort selection based on each model's supported range
- Web search mode selectable as `Auto`, `Always on`, or `Off`
- Real-time token streaming with response latency display
- Per-user chat history, automatic title generation, and individual/bulk deletion
- Per-user personal memory: create, update, delete, and inject into response context
- File attachments: images, PDF, Office documents, and TXT/Markdown/CSV/JSON files
- PowerPoint (`.pptx`) generation from web search results and attachments, with download
- Laptop-first ChatGPT-style UI with responsive mobile layout
- Copilot connection/loading/error status indicators, model retry, and automatic last-conversation restore
- SQLite WAL mode locally; safe rollback-journal-based persistent storage on network storage (App Service)

## Architecture

```text
Browser
  -> FastAPI web app (login, history, memory, SQLite)
  -> Microsoft Foundry Hosted Agent (Responses protocol)
  -> GitHub Copilot Python SDK (model discovery)
  -> GitHub Copilot CLI runtime (selective web_search + attachments)
  -> Copilot-provided GPT / Claude / Gemini / MAI models
```

| Path | Role |
|---|---|
| `src/my_copilot_agent/` | Foundry Hosted Agent and Copilot SDK adapter |
| `src/my_chat_web/` | FastAPI web app, authentication, SQLite, UI |
| `tests/` | Auth, isolation, CRUD, and protocol tests |
| `azure.yaml` | Foundry Hosted Agent definition with no model deployments |

## GitHub Copilot Authentication

Locally, the existing Copilot CLI login session can be used. Deployed environments are headless, so `COPILOT_GITHUB_TOKEN` is required. Accepted token types: GitHub CLI OAuth token, fine-grained PAT with Copilot Requests permission, or Copilot CLI OAuth token. Classic `ghp_` PATs are not supported.

Set the OAuth token for a specific GitHub account in the azd environment:

```bash
azd env set COPILOT_GITHUB_TOKEN "$(gh auth token --user <github-user>)"
```

`azd provision` stores this value as a write-only secret in the `my-chat-runtime-secrets` CustomKeys connection in Foundry. The agent version retains only the reference `${{connections.my-chat-runtime-secrets.credentials.github_token}}`, never the token value itself. Do not place the token in source code, `.env.example`, commits, or logs. `.azure/` and `.env` are excluded from Git.

## Local Development

### 1. Hosted Agent

```bash
cd src/my_copilot_agent
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cd ../..

AZURE_DEV_USER_AGENT=microsoft_foundry_skill \
  azd ai agent run my-chat --no-client
```

In a separate terminal:

```bash
AZURE_DEV_USER_AGENT=microsoft_foundry_skill \
  azd ai agent invoke my-chat --local "Hello"
```

### 2. Web App

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r src/my_chat_web/requirements-dev.txt

cd src/my_chat_web
export APP_SESSION_SECRET="<random string, 32+ characters>"
export MY_CHAT_BOOTSTRAP_PASSWORD="<temporary first-login password>"
export FOUNDRY_AGENT_ENDPOINT="http://localhost:8088/responses"
../../.venv/bin/uvicorn main:app --reload
```

Open `http://localhost:8000` to log in. On first login all users use the bootstrap password and are immediately prompted to set their own password.

## Foundry Deployment

For a first deployment, create the Sweden Central environment once:

```bash
AZURE_DEV_USER_AGENT=microsoft_foundry_skill \
  azd env new my-chat-dev --location swedencentral --no-prompt
```

Then run the deployment commands from the project root:

```bash
AZURE_DEV_USER_AGENT=microsoft_foundry_skill azd provision --no-prompt
AZURE_DEV_USER_AGENT=microsoft_foundry_skill azd deploy --no-prompt
AZURE_DEV_USER_AGENT=microsoft_foundry_skill azd ai agent show --output json
AZURE_DEV_USER_AGENT=microsoft_foundry_skill \
  azd ai agent invoke my-chat "Hello"
```

`azd deploy` uses `codeConfiguration` for direct code deployment. No Docker/ACR or Foundry model deployment is required.
New environments and the recreation workflow use Sweden Central by default. Changing this default does not move existing Azure resources.

## Full Azure Recreation

To recreate Foundry, App Service, managed identity, RBAC, and app settings from scratch under the `my-chat` name, follow the [Azure Recreation Guide](docs/azure-recreation.md).

```bash
./scripts/recreate-azure.sh
```

The recreation script excludes local `data/`, uploads, SQLite files, `.env`, and logs from the deployment ZIP. Deployment is considered complete only after both a Hosted Agent invocation and a web app `/healthz` check succeed.

The web UI is deployed to a separate Azure App Service with the following app settings:

| Setting | Value |
|---|---|
| `APP_ENV` | `production` |
| `APP_SESSION_SECRET` | Random secret, 32+ characters |
| `MY_CHAT_BOOTSTRAP_PASSWORD` | Temporary password for first login |
| `MY_CHAT_DATABASE_PATH` | `/home/data/my-chat.db` |
| `MY_CHAT_UPLOAD_DIR` | `/home/data/uploads` |
| `FOUNDRY_AGENT_ENDPOINT` | Deployed Hosted Agent Responses endpoint |
| `FOUNDRY_TOKEN_SCOPE` | `https://ai.azure.com/.default` |
| `ALLOWED_HOSTS` | Web app hostname |
| `WEBSITES_ENABLE_APP_SERVICE_STORAGE` | `true` |
| `FORWARDED_ALLOW_IPS` | `*` |

Grant the web app's system-assigned managed identity the `Foundry User` role scoped to the Foundry project. In production, only `ManagedIdentityCredential` is used—not `DefaultAzureCredential`.

The FastAPI startup command must handle HTTPS proxy headers from App Service:

```bash
python -m uvicorn main:app --host 0.0.0.0 --proxy-headers
```

Use this together with the `FORWARDED_ALLOW_IPS=*` app setting. Static assets use same-origin relative paths, so a misconfigured proxy will not cause CSP to block CSS/JavaScript.

## Operational Notes

- Model availability depends on the Copilot subscription plan and organization policy. On a healthy connection, the UI uses the live results of `CopilotClient.list_models()`. If the call fails, the UI falls back to a configured fallback list and shows a warning, but actual availability is not guaranteed.
- `Auto` lets the model decide whether web search is needed; `Always on` forces the web tool to run with a fast search model; `Off` excludes the web tool from the session entirely.
- The web app reuses per-user Foundry sessions. Sessions are never shared across users, and subsequent requests from the same user reuse the existing session to avoid repeated connection-initialization latency.
- Supported attachment types: TXT, Markdown, CSV, JSON, PDF, PNG/JPG/GIF/WebP, DOCX, XLSX, PPTX. Limits: 8 MB per file, 5 files and 16 MB total per request.
- TXT/Markdown/CSV/JSON files are passed as citation context; images, PDF, and Office documents are passed as native Copilot attachments.
- Generated PPTX files and uploads are stored under `/home/data/uploads` with per-user, per-conversation randomized filenames. Only the owning user can download them.
- Full response text is stored as-is. When reused as conversation context in a subsequent request, it is truncated to 20,000 characters per message to respect protocol limits and keep response times acceptable.
- The SQLite file assumes a single low-traffic web instance. If you scale to multiple instances, migrate to Azure SQL or PostgreSQL.
- Changing the bootstrap password does not reset existing users' passwords.
- User memory and chat history are always filtered by user ID.
- The Hosted Agent exposes no file or shell tools; only the limited `web_search`/`web_fetch` tools are available, and only when the user enables them.
